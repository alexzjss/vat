# M2 — Mapa-múndi, área local e encontro no mapa: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ciclo jogável mapa-múndi → área local → encontro com inimigo visível → batalha ATB do M1 no próprio mapa → volta à exploração → saída ao mapa-múndi, com Game Over voltando ao ponto de salvamento.

**Architecture:** Lógica nova pura em `game/core/` (estado de jogo + ponto de salvamento, comportamento de movimento de inimigo, definição de encontro). Cenas novas em `game/world/` (jogo raiz com transições, jogador, inimigo de mapa, arena, mapa-múndi, área local). A batalha do M1 (`BattleScene`) ganha um **modo mapa** e é instanciada dentro da área local nas coordenadas do mapa — sem duplicar a lógica de batalha.

**Tech Stack:** Godot 4.7 (GDScript tipado), GUT 9.7.1, `./run_tests.ps1`.

**Spec:** [`.claude/specs/2026-10-18-m2-mapa-design.md`](../specs/2026-10-18-m2-mapa-design.md) (o design do M2; seção 7 tem as escolhas a seguir) e, para regras de batalha, [`2026-10-18-rpg-design.md`](../specs/2026-10-18-rpg-design.md).

## Global Constraints

- Todas as restrições globais do plano M1 continuam: tipos estáticos em toda declaração (`untyped_declaration` = erro), `game/core/` sem `Node`/`Input`/cenas, aleatoriedade só via `Dice`, números de balanceamento só em `BalanceConfig` (valores de teste), identificadores em inglês e texto de UI em português, conteúdo genérico sem narrativa.
- **Os 144 testes do M1 continuam passando** em toda task.
- Nada de arte: formas e cores lisas (`ColorRect`, `Polygon2D`, `_draw`).
- Camadas de colisão (fixas para todas as tasks): **1 = paredes/obstáculos**, **2 = jogador**, **3 = inimigos de mapa**. Jogador: layer 2, mask 1+3. Inimigo: layer 3, mask 1. Área de toque do inimigo (`Area2D`): layer 0, mask 2. Zonas (entrada de local, saída): layer 0, mask 2.
- Ações de input novas em `project.godot`: `move_up` (↑, W), `move_down` (↓, S), `move_left` (←, A), `move_right` (→, D).
- Sem batalhas no mapa-múndi. HP/Aura persistem entre batalhas. Inimigo comum reaparece ao reentrar na área.

## Review Focus

1. **Jogador preso após a batalha** (ponto do líder dentro de colisão ou sobre o inimigo): o líder volta ao `HeroSpot1` da arena; o design do mapa garante que é espaço livre, e o teste da Task 6 verifica que ele consegue se mover depois. → `test_player_can_move_after_victory`.
2. **Reentrar no local sem querer** ao voltar ao mapa-múndi: o retorno é num marcador fora da zona de entrada. → Task 8 `test_exit_returns_beside_location_not_inside`.
3. **Encostar de novo / dois encontros simultâneos** (o toque dispara duas vezes, ou durante a transição): o encontro só começa uma vez; toques durante batalha/transição são ignorados. → Task 6 `test_touch_twice_starts_one_battle`.
4. **Game Over com estado sujo**: restaurar o salvamento devolve HP/AP/XP/nível/alocação/pendentes e inventário exatamente como no início, sem compartilhar objetos com o estado perdido. → Task 1 `test_restore_is_deep_and_independent`.
5. **Inventário compartilhado entre batalhas no mapa**: o item gasto numa batalha não volta na seguinte; a batalha isolada do M1 continua com inventário próprio. → Task 3 `test_map_mode_uses_given_inventory`.

### Task 2: `EncounterDef` e movimento de inimigo de mapa

**Files:**
- Create: `game/core/defs/encounter_def.gd`, `game/core/world/map_movement.gd`, `game/core/world/wander_movement.gd`, `game/tests/test_wander.gd`, `game/data/test/encounters/encontro_xy.tres`
- Modify: `game/tests/test_content.gd` (carrega o encontro)

**Interfaces:**
- Produces:
  - `EncounterDef extends Resource`: `@export var id: StringName`, `@export var enemies: Array[EnemyDef]`. `encontro_xy.tres` = [inimigo_x, inimigo_y].
  - `MapMovement extends RefCounted`: `func step(pos: Vector2, delta: float) -> Vector2` (velocidade desejada; base devolve `Vector2.ZERO`). É a interface plugável do design §4.6.
  - `WanderMovement extends MapMovement`: `_init(region: Rect2, cfg: BalanceConfig, dice: Dice)`. Começa em WAIT. Estados WAIT → MOVE: no passo em que o tempo de espera acaba, sorteia o alvo, muda para MOVE e ainda devolve `ZERO`; o movimento começa no passo seguinte. Em WAIT conta `wait_min + roll()*(wait_max-wait_min)`; ao fim sorteia um alvo `region.position + Vector2(roll(), roll()) * region.size`; em MOVE devolve `(alvo - pos).normalized() * wander_speed` até `distância <= wander_arrive_dist` (então WAIT). **Preso:** se em MOVE a posição avançou menos que `wander_arrive_dist` durante `wander_stuck_time`, volta a WAIT. Se `pos` estiver fora da região, o alvo é o ponto mais próximo dentro dela. `var target: Vector2` legível para testes.

# game/tests/test_wander.gd
extends GutTest
var cfg: BalanceConfig
func before_each() -> void:
	cfg = Fixtures.cfg()
func _run(m: WanderMovement, pos: Vector2, seconds: float) -> Vector2:
	var t := 0.0
	while t < seconds:
		pos += m.step(pos, 0.05) * 0.05
		t += 0.05
	return pos
func test_waits_then_moves_toward_target_in_region() -> void:
	var r := Rect2(0, 0, 100, 100)
	var m := WanderMovement.new(r, cfg, ScriptedDice.new([0.0, 0.5, 0.5]))
	assert_eq(m.step(Vector2(10, 10), 0.6), Vector2.ZERO)
	var v := m.step(Vector2(10, 10), 0.05)
	assert_true(r.has_point(m.target))
	assert_almost_eq(v.length(), cfg.wander_speed, 0.001)
func test_never_leaves_region_over_time() -> void:
	var r := Rect2(50, 50, 120, 80)
	var m := WanderMovement.new(r, cfg, Dice.new(3))
	var pos := Vector2(100, 90)
	for i: int in 400:
		pos += m.step(pos, 0.05) * 0.05
		assert_true(r.grow(cfg.wander_arrive_dist).has_point(pos))
func test_stuck_returns_to_wait() -> void:
	var m := WanderMovement.new(Rect2(0, 0, 100, 100), cfg, ScriptedDice.new([0.0, 1.0, 1.0]))
	m.step(Vector2.ZERO, 1.0)
	var stuck := Vector2(5, 5)
	for i: int in 20:
		m.step(stuck, 0.05)
	assert_eq(m.step(stuck, 0.05), Vector2.ZERO)
func test_deterministic_with_same_seed() -> void:
	var r := Rect2(0, 0, 200, 200)
	assert_eq(_run(WanderMovement.new(r, cfg, Dice.new(7)), Vector2(100, 100), 10.0), _run(WanderMovement.new(r, cfg, Dice.new(7)), Vector2(100, 100), 10.0))

### Task 6: Área local com encontro no mapa

**Files:**
- Create: `game/world/local_map.tscn`, `game/world/local_map.gd`, `game/tests/test_local_map.gd`

**Interfaces:**
- Consumes: `GameState`, `Player`, `MapCamera`, `MapEnemy`, `BattleArena`, `Zone`, `BattleScene` (modo MAP, `start_with`, `finished`).
- Produces:
  - Cena `local_map.tscn` (≈ 2 telas, 2400×720): fundo, paredes de borda e 3–4 obstáculos (`StaticBody2D` layer 1 com `ColorRect`), `Marker2D` `Entry` (perto da saída, dentro), `Zone` `Exit` (zone_id `&"exit"`, rótulo "Saída"), um `MapEnemy` com `encontro_xy.tres` e `region` num espaço aberto, uma `BattleArena` nesse espaço (3 heróis à esquerda, 2 inimigos à direita, tudo cabe em 1280×720 centrado), `Player`, `MapCamera`.
  - `LocalMap extends Node2D`: `signal exit_requested`, `signal game_over`. `func setup(state: GameState, spawn: StringName) -> void` (posiciona o jogador no marcador; câmera segue; `setup` de cada inimigo com `state.cfg`/`state.dice`). `var battle: BattleScene` (null fora de batalha). `var auto_battle: bool = false` (repassado à batalha; testes/demo).

  - `finished(DEFEAT)`: emite `game_over` (o `Game` cuida do resto).
  - `Exit.entered` → emite `exit_requested` (só se não houver batalha).
